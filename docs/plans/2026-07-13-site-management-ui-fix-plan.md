# 站点管理与网址编辑修复计划

> **状态：Superseded。** 本文仅保留为历史修复记录；当前版本不支持批量导入，也不应依据本文恢复该功能。

## 目标

让用户在一个清晰的工作区内完成三件事：找到站点、快速修改网址与接口、可靠地新增站点。任何校验失败都不能改写运行中的配置。

## 审查结论

- 设计基线：D。功能存在，但配置中心横向溢出，核心详情不可见，操作层级不清。
- AI Slop：A。没有装饰性卡片或渐变问题，主要问题是传统表格式表单堆叠和过度留白。
- 高影响问题：配置中心把所有字段塞进横向表格，1360px 下右侧内容仍被裁切；保存、复制、删除都依赖不明显的复选框。
- 高影响问题：快速新增、空白新增和复制共用同一组变量，切换模式会残留或覆盖值；快速模式高级项重复显示网址。
- 高影响问题：空白新增忽略接口路径，快速新增忽略自定义站点标识，批量导入不校验发布时间，也不统一创建配套文件。
- 中影响问题：错误只显示在底部状态文字，离出错字段远；创建按钮名称不随模式变化。
- 中影响问题：批量导入把格式说明直接写进编辑框，用户必须先识别哪些是说明、哪些是数据。

## 交互方案

1. 配置中心改为左侧站点列表、右侧单站点编辑器。列表只承担选择和状态浏览，编辑器承担网址、接口、分类、间隔、上限和启用状态的修改。
2. 工具栏保留四个明确动作：新增站点、复制当前站点、删除当前站点、打开调度；右上角提供唯一主操作“保存更改”。
3. 切换站点时先把当前表单写入内存草稿；点击保存时一次性校验全部草稿，通过后才创建新的 `SiteConfig` 列表并替换运行配置。
4. 新增弹窗使用模式标签，但每个模式只显示该模式所需字段。快速新增默认只有网址和 API Key，高级项只显示站点标识、接口路径、分类和发布设置，不重复网址。
5. 空白新增改为“完整配置”，接口输入保存到 `jiekou`；快速新增尊重用户填写的站点标识。
6. 批量导入把格式说明放到只读帮助区，输入框保持空白；逐行报告行号，并校验 URL、数字、发布时间和重复名称。
7. 所有创建路径统一规范化 URL、创建配套目录/文件，并在成功后立即保存与刷新列表。

## 测试与验收

- 回归测试覆盖：快速新增自定义标识、空白新增接口、批量发布时间校验、批量配套文件创建、配置中心校验失败不修改原对象。
- UI 冒烟覆盖：列表选择驱动编辑器、复制/删除使用当前选择、按钮文案随模式变化。
- 完整执行 `pytest`、`compileall` 和 `ruff`。
- 保存前后四张对应截图：配置中心、快速新增、完整配置、批量导入。
- 验收标准：1200×720 下无横向滚动；当前站点和主操作明确；常用网址修改不超过“选择站点、改网址、保存”三步。

## 风险

- 项目没有 Git 元数据，无法按 design-review 要求逐项原子提交；用前后截图、测试和文件清单替代。
- 本轮只重构站点管理和新增流程，不扩展发布调度、失败重试或网络安全修复。
