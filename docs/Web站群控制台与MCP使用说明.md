# AnqiCMS Web 站群控制台与 MCP 使用说明

`AnQiCMS Web 站群控制台` 是基于本地轻量 HTTP 服务与现代 Web 前端构建的站群一体化管理台，同时内置 **真·免密后台代理** 与 **MCP (Model Context Protocol) 服务端**，既可双击作为桌面应用使用，也可部署在 VPS / 挂机宝上远程管理。

---

## 一、快速启动与运行模式

### 1. 本地桌面使用（推荐）

- **打包版**：直接双击运行 `anqicms站群控制台.exe`。
- **源码版**：在项目根目录执行：

```bash
python web_app.py
```

程序启动后会自动绑定本地可用端口（也可通过 `--port` 固定端口），优先尝试调用 **Microsoft Edge / Google Chrome 的 `--app` 独立应用窗口模式**打开控制台；若未检测到 Edge/Chrome，则自动回退到系统默认浏览器新标签页。

> 关闭黑色控制台窗口或按 `Ctrl + C`，即可自动停止 Web 控制台、`*.localhost` 后台代理、后台任务队列及数据库释放资源。

### 2. VPS / 挂机宝远程启动

在服务器或挂机宝上以无头服务模式运行，固定端口并监听所有网卡：

```bash
anqicms站群控制台.exe --host 0.0.0.0 --port 18900 --no-browser
```

源码环境命令：

```bash
python web_app.py --host 0.0.0.0 --port 18900 --no-browser
```

- 启动后通过浏览器访问：`http://<服务器公网或内网IP>:18900`
- 如需接入远程 MCP 客户端，接口地址为：`http://<服务器IP>:18900/mcp`
- **安全建议**：远程放行端口时，建议配合服务器安全组/防火墙限制仅允许可信来源 IP 访问，避免暴露站点管理入口。

### 3. 完整启动参数一览

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `--host` | `127.0.0.1` | HTTP 服务监听地址；远程访问设为 `0.0.0.0` |
| `--port` | `0`（自动） | 监听端口，`0` 表示自动分配空闲端口 |
| `--config` | 自动查找 `config.ini` | 指定配置文件路径（支持多套站群配置切换） |
| `--mode` | `app` | `app` 优先独立应用窗口；`browser` 总是打开浏览器标签页 |
| `--no-browser` | 关闭 | 无头模式，仅启动后端服务与 `/mcp` 接口 |
| `--tk` | 关闭 | 启动旧版 Tkinter 桌面界面（保留兼容入口） |
| `--mcp-stdio` | 关闭 | 以标准输入输出（stdio）方式运行 MCP 服务端 |

## 二、6 大核心功能模块速查

### 1. 总览看板（Dashboard）
- 实时汇总站群总站点数、启用/停用数、分组分布、MCP 就绪状态、待升级站点数与友链审计状态。
- 支持一键发起全站 MCP 连通性探测（`probe-mcp`）、查看最新发布任务统计与实时审计日志。

### 2. 5 合 1 友链中心
- **批量加链 / 批量下链**：支持 HTML `<a>` 标签、`标题|URL`、多行 URL 等格式一键解析并并发写入或下链，自动跳过本站域名并去重。
- **单站友链管理**：直接查看和编辑任意站点的当前友情链接列表。
- **导出 HTML 友链代码**：按分组或指定站点批量生成标准 `<a href="...">` 代码片段，自动支持多标题池首条提取与 `rel="nofollow"` 选项。

### 3. 全站反链巡检与一键清掉链
- 并发爬取各站点外链目标页面，核验对方站点是否保留我方反链（支持 `ok` / `missing` 等状态记录并持久化到 `SiteGroupDB` 历史）。
- 支持配置 **白名单域名**，保护重要合作友链或主站不被误删。
- 巡检结束后可预览缺失反链列表，确认后一键清理掉链。

### 4. 全站查链（跨站实时检索）
- 跨所有站点（或按分组筛选）并发查询某条友链或某个域名存在于哪些站群站点。
- 支持 **根域名等价匹配**（如自动匹配带 `www.` 与不带 `www.` 的变体）以及按链接 URL、标题或备注过滤。

### 5. SEO 稀疏 / 跨组互链与锚文本轮换
- 内置 5 种站群互链拓扑策略：
  - `mesh`：全网互链
  - `hub`：中心主站辐射互链
  - `ring`：环形链轮
  - `random_k`：随机 K 链（支持避开双向对链 `avoid_reciprocal` 与同根域名 `avoid_same_root_domain`）
  - `group_cross`：跨分组互链（在 A 组与 B 组间稀疏建链）
- 支持 **多标题锚文本轮换**（站群设置中用 `|` 分隔多个关键词标题，互链时自动按轮换策略取词，避免全站锚文本单一）。
- **先预览、后写入、可回滚**：每次互链执行均写入回滚台账（`plan_id`），支持随时按计划 ID 一键精确撤销该次新增的全部友链。

### 6. 批量导入新站、统一升级与可视化设置
- **批量建站与自动探测**：支持多行文本导入（`站点名|网址或导入接口|分组|MCP_Token|后台账号|后台密码|站点名称` 或单列域名/URL），可自动探测站点首页标题、友链数量与 MCP 接口状态，并自动补齐发布目录与基础文件。
- **统一检查与金丝雀升级**：批量检查各站 AnqiCMS 当前版本与最新版本；执行升级时默认采用 **金丝雀先行**（先升级第 1 站并等待健康探活恢复）+ **失败即停** + 可调并发（1~5），最大限度降低批量升级风险。
- **可视化设置与文章发布**：在线维护站群高级参数（MCP 超时/SSL 校验、友链白名单与确认阈值、后台跳转策略、升级健康检查、本地发布任务启停与日志查看）。

## 三、真·免密直跳后台（`*.localhost` 本地代理原理）

传统站群工具打开多个 AnqiCMS 后台时，容易因为同一浏览器会话、跨域 `localStorage` Token 注入限制或登录态冲突导致跳转失败或串号。

本工具采用 **三级智能回退 + 本地回环隔离代理（`AdminProxyServer`）** 解决该问题：

1. **三级跳转策略（`ticket` -> `bridge` -> `direct`）**
   - 优先通过 MCP / 登录凭证换取一次性票据或上游已认证会话（`ticket`）。
   - 若站点支持代理会话引导，则通过本地代理启动已认证的 `/system/` 后台（`bridge`）。
   - 若以上不可用，则自动安全回退到常规后台地址（`direct`）并给出清晰原因说明。
2. **为什么无需修改 `hosts` 文件？**
   - 现代浏览器（Chrome / Edge / Firefox）原生遵循 RFC 6761 规范，会自动将所有 `*.localhost` 子域名解析到 `127.0.0.1`。
   - `AdminProxyServer` 为每个站点生成独立的源地址（如 `http://<site-slug>.localhost:<代理端口>/system/`）。
   - 每个站点的 `localStorage` Token 与上游后台 Cookie 均严格隔离在各自的 `<site-slug>.localhost` 源下，做到 **无需改 `hosts`、不串号、多站同时免密直达后台**。

## 四、作为 MCP Server 接入 AI 客户端

本控制台同时提供 **Streamable HTTP（`/mcp`）** 与 **Stdio** 两种 MCP 接入方式，可直接从控制台「设置 / MCP 接入」页面一键复制对应 JSON 配置，或参考下方模板。

### 方式 A：HTTP Streamable 模式（推荐，控制台运行期间可用）

当 `web_app.py` 或 `anqicms站群控制台.exe` 正在运行时，MCP 接口直接挂载在 `/mcp` 路径上（默认端口若需固定，启动时加 `--port 18900`）：

```json
{
  "mcpServers": {
    "anqicms-sitegroup": {
      "type": "http",
      "url": "http://127.0.0.1:18900/mcp"
    }
  }
}
```

> 提示：若在 Cursor / Antigravity / Claude 中配置 HTTP 模式，请确保以固定端口启动控制台（例如 `--port 18900`），这样重启工具后 URL 不会变化。

### 方式 B：Stdio 模式（由 AI 客户端按需自动拉起）

**1. 打包版（`anqicms站群控制台.exe`）：**

```json
{
  "mcpServers": {
    "anqicms-sitegroup": {
      "command": "E:\\path\\to\\anqicms站群控制台.exe",
      "args": [
        "--mcp-stdio",
        "--config",
        "E:\\path\\to\\config.ini"
      ]
    }
  }
}
```

**2. 源码版（`mcp_server.py`）：**

```json
{
  "mcpServers": {
    "anqicms-sitegroup": {
      "command": "python",
      "args": [
        "E:\\path\\to\\anqicms\\mcp_server.py",
        "--config",
        "E:\\path\\to\\anqicms\\config.ini"
      ]
    }
  }
}
```

### 内置 12 个 MCP 工具清单与 AI 指令示例

| 工具名 | 作用说明 | 典型 AI 自然语言指令示例 |
| :--- | :--- | :--- |
| `list_sites` | 列出站群站点，支持按分组、关键词、启用状态筛选并附带缓存统计 | 「帮我列出分组 `搬家站` 下所有已启用的站点，看看哪些还没配好 MCP Token。」 |
| `search_links` | 跨站点并发检索友链（支持根域名等价匹配） | 「查一下全站哪些站点还挂着 `example.com` 的友链。」 |
| `batch_add_links` | 向多个站点或指定分组批量添加友链（自动去重、跳过本站） | 「给 `A组` 所有站点批量加上友链 `示例站|https://example.com`。」 |
| `batch_remove_links` | 从多个站点批量删除指定友链 | 「把 `https://old-site.com` 从全站友链里统一下掉。」 |
| `audit_backlinks` | 并发巡检对方反链存活情况，支持白名单与确认后清掉链 | 「先帮我巡检全部站点的反链情况（不要删除），把掉链站点汇总给我；确认后再清理掉链。」 |
| `crosslink_plan` | 规划或执行站群互链（`mesh`/`hub`/`ring`/`random_k`/`group_cross`），默认 `dry_run=true` 预览 | 「用 `group_cross` 模式在 `A组` 和 `B组` 之间做跨组互链预览，每站最多 2 条，避开同根域名。」 |
| `rollback_crosslink` | 按互链台账 `plan_id` 精确回滚该次新增的友链（需确认） | 「帮我把刚才执行的互链计划 `plan_2026xxxx` 完整回滚撤销。」 |
| `export_html_links` | 导出选定站点或分组的标准 HTML `<a>` 友链代码 | 「导出 `主站组` 所有站点的 HTML 友链代码给我。」 |
| `check_versions` | 并发检测站点当前版本、最新版本与可升级状态 | 「检查全部站点的 AnqiCMS 版本，列出有哪些站点可以升级。」 |
| `upgrade_sites` | 分阶段执行系统升级（金丝雀第 1 站、失败即停，需 `confirmed=true`） | 「确认将 `测试组` 站点执行金丝雀升级，先升第 1 站并开启失败即停。」 |
| `get_admin_jump_url` | 解析指定站点的后台免密跳转 URL（返回脱敏地址与分级信息） | 「帮我获取站点 `site_01` 的后台免密跳转地址。」 |
| `import_sites` | 解析批量建站文本（默认仅预览，`save=true` 持久化，可选自动探测） | 「帮我解析并探测这批新站清单（先预览不保存）：`siteA|https://a.com|新站组|token123`。」 |

> **安全机制提示**：涉及删除/写入/升级的高危工具（如 `audit_backlinks` 清理掉链、`crosslink_plan` 写入、`rollback_crosslink`、`upgrade_sites`）均强制设有 `dry_run` 或 `confirmed=true` 二次确认门禁，且所有日志与返回信息均经过凭据脱敏处理。
